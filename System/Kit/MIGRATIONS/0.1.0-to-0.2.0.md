# 0.1.0 to 0.2.0

This release adds Context Packs. Kit-owned rules, templates, validators, Core Skills, and documentation change. Existing User-owned content does not move. The Seeded `Skills/Enabled.md` needs one reviewed reconciliation because a seventh mandatory Core Skill is added; every existing Personal Skill entry must remain. Pack Definitions, `.gitmodules`, and Submodule pointers are User-owned and must be preserved during this and later upgrades.

## Preconditions

- Commit or deliberately shelve every personal change.
- Confirm that personal `main` and the private `origin` contain the intended recovery point.
- Read the Context Pack changelog and inspect the merge before pushing it.

## Upgrade

```sh
git switch kit-base
git fetch kit --tags
git merge --ff-only kit/main
git switch main
git merge --no-ff v0.2.0 -m "kit: upgrade to v0.2.0"
```

If `Skills/Enabled.md` conflicts, preserve its personalized content and add this exact Core Skill entry once:

```md
- [[Skills/Kit/lbrain-context-pack/SKILL]] — codex, claude, hermes
```

This reconciliation is required because the Full profile has no Minimal variant. Do not replace the whole Seeded file. Preserve user-owned Pack files if a conflict exists. Then restore registered Pack repositories, if any:

```sh
git submodule sync --recursive
git submodule update --init --recursive
python3 System/Kit/check.py
python3 -m unittest discover -s System/Kit/tests -v
```

Submodule restoration may require access to each Pack remote. Lack of access must not be resolved by deleting its Definition or registration.

## Validation

- The validator reports zero errors.
- `Skills/Enabled.md` contains all seven Core Skills plus every pre-existing Personal Skill entry.
- Existing personal context, Personal Skills, Pack Definitions, `.gitmodules`, and Submodule pointers remain present.
- `git diff v0.1.0...HEAD` contains only understood Kit changes and preserved personal merge history.

## Rollback

Do not rewrite or reset a shared personal branch. Revert the upgrade merge with `git revert -m 1 <upgrade-merge-commit>`, validate, and push the revert only after review. Independently published Pack releases are unaffected by a Kit rollback.
