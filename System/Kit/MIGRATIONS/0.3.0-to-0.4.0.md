# Migration: 0.3.0 to 0.4.0

This required Kit migration adds deterministic Personal Intelligence write operations. It does not require a bulk rewrite of personal content.

## Affected ownership

- **Kit-owned:** `System/Kit/` and the Capture, Weave, and Skill Manager packages under `Skills/Kit/` are updated by the release.
- **Seeded:** no required change. Preserve the personalized `Skills/Enabled.md` exactly.
- **User-owned:** existing Projects, Sources, Proposals, Personal Skills, and runtime state are preserved.

## Preconditions

1. Commit or back up all personal changes.
2. Read `System/Kit/CHANGELOG.md` and confirm the selected release is exactly `v0.4.0`.
3. Confirm `python3 System/Kit/check.py` passes before the merge.

## Upgrade

Follow `System/Kit/SETUP.md` and merge only the `v0.4.0` tag into personal `main`. Then run:

```sh
python3 System/Kit/check.py
python3 System/Kit/Examples/Tracer/run.py
```

Runtime installation remains opt-in. Symlink-installed Codex, Claude Code, and Hermes Skills follow the canonical packages. OpenClaw copies change only when an approved Skill application or explicit installer refresh names that target.

## Lazy v1 boundaries

- Existing Project notes remain valid. The first approved `project.configure` apply wraps an existing `## Context Intake Profile` body in v1 markers without rewriting that body; Projects without a Profile are unchanged until configured. A legacy Profile without the canonical `### Sources and anchors` rows stays preserved but must be explicitly reconfigured before `project.checkpoint` can enforce source-and-anchor completeness.
- Connector credentials, raw cursors, and local execution logs remain outside canonical Markdown and Git. `project.checkpoint` rejects a raw cursor and does not advance the last complete checkpoint after a required-source failure.
- Existing Sources remain valid and are not backfilled in bulk. `capture.create` reuses a matching legacy `origin`; new captures also receive a stable `capture_id`.
- Existing Personal Skills remain unchanged until an evidence-linked Proposal has an exact Change Preview and that exact preview hash is approved. A changed base Skill invalidates the preview.

## Validation

The migration is complete when the Kit validator and Personal Intelligence tracer pass, personal files remain present, and `git diff` shows no unintended replacement of Seeded or User-owned content.

## Rollback

If validation fails, abort the merge before committing or revert only the local upgrade merge commit. Restore personal files from the pre-upgrade commit or backup; do not delete or regenerate User-owned directories. Runtime symlinks need no rollback, while an explicitly refreshed OpenClaw copy can be restored from its pre-upgrade package backup.
