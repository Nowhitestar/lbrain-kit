# 0.2.4 to 0.3.0

This release adds the portable Skill contract and the first-class retrieval provider layer.

## Affected ownership

- **Kit-owned:** Core Skills, `System/Kit/`, validators, runtime docs, and tests are replaced by the release.
- **Seeded:** `Skills/Enabled.md` may be reconciled to add `openclaw` without removing personal entries or runtime choices.
- **User-owned:** each Personal Skill moves LBrain lifecycle and provenance keys from `SKILL.md` into a new `lbrain.json`. Skill instructions and resources remain unchanged.

## Preconditions

1. Commit or otherwise back up the current LBrain.
2. Record any runtime copies that are not symlinks; they will need a reviewed reinstall.
3. Do not merge the release while a Personal Skill migration is partially applied.

## Required Personal Skill migration

For every `Skills/Personal/<name>/SKILL.md`:

1. Keep only `name` and `description` in YAML frontmatter.
2. Create `Skills/Personal/<name>/lbrain.json` with `schema`, `version`, `status`, `visibility`, `created`, and `updated`.
3. Move `license` and provenance fields such as author, repository, origin, or source commit into the sidecar.
4. Preserve the Skill body and every resource byte-for-byte unless a separate authorized change exists.
5. For public Personal Skills, keep the matching `LICENSE` or `LICENSE.md` file.

Example:

```json
{
  "schema": "lbrain.skill.v1",
  "version": "1.0.0",
  "status": "active",
  "visibility": "private",
  "created": "2026-08-07",
  "updated": "2026-08-09"
}
```

## Optional Seeded reconciliation

Add `openclaw` to selected `Skills/Enabled.md` entries only when this LBrain should install those packages into an OpenClaw-visible directory. Preserve every existing Personal Skill entry and runtime selection.

## Retrieval setup

1. Reinstall or relink the Core Skills for each selected runtime.
2. Preview and apply `lbrain-retrieve/scripts/retrieval.py register --root <lbrain-root>` for copy-installed runtimes such as OpenClaw.
3. Run `doctor`; use `LBRAIN_ROOT` or `--root` when a local registry is intentionally not used.
4. Reuse an existing matching qmd index, or preview `configure` before applying a dedicated `lbrain` index.
5. Run `update`, `embed`, and `doctor --require-qmd` when qmd is required.

## Validation

```sh
python3 System/Kit/check.py
python3 -m unittest discover -s System/Kit/tests -p 'test_*.py'
```

Run the current Codex `quick_validate.py` against each installed Skill when Codex is one of the targets.

## Rollback

Revert the 0.3.0 merge or restore the pre-migration commit. qmd configuration and indexes are derived state outside the repository; removing a newly created dedicated `lbrain` config and index does not remove LBrain Markdown. Do not delete a pre-existing shared qmd index during rollback.
